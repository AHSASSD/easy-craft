# 启动前自动补齐与真实整合包验证

测试对象：用户指定的 `E:\minecraft\versions\苍蓝天鹅绒的彼端`，Minecraft 1.21.1 / NeoForge 21.1.265。

## 复现与根因

真实 EXE 的系统目录选择、扫描和直接添加均成功，识别一个存档；首次启动准备失败，缺少该 NeoForge 版本的 universal.jar 和经过处理器生成的 client.jar。原安装的 libraries 只有其他 NeoForge 版本的文件，不能替代 21.1.265。用户原目录已有的失败日志也报告 Minecraft / NeoForge 核心模块缺失。

旧启动链路只检查文件位置并报错，未执行补全。client.jar 并非 Maven 可直接下载的文件，必须通过对应官方安装器处理器生成。

## 实施

- 本地实例点击启动后自动补齐元数据声明的缺失基础库、Windows 原生库、客户端、资源索引及资源对象。采用 HTTPS 官方来源、声明的 SHA-1/大小、已有下载缓存及取消机制；无法确认来源与校验信息的文件不猜测替代。
- 缺少 NeoForge 处理器产物时，下载并校验对应官方安装器 SHA-1，在启动器独立 repair 目录执行 `--installClient`，仅提交缺失的已生成 JAR，不覆盖已有文件。处理器依赖通过启动器下载器预先校验补齐，避免 Java 下载连接超时。存档和账号不传入处理器目录。
- 修复后重新执行原启动环境检查，再创建游戏进程。任务显示下载项目进度、处理器阶段和失败日志路径；取消保留已校验缓存。处理器本身未提供可信百分比时不伪造进度。
- 更新本地导入文案：添加时不联网，启动时可自动补全。诊断仍为建议，不因 JEI 等声明警告禁用启动；不会擅自升级、降级或移除 Mod。
- 测试截图工具支持 Sodium 改写操作系统进程标题，继续严格核对启动器父进程、Java 路径和隔离目录边界。

## 验证

`scripts/verify-azure-launch.mjs` 使用真实 EXE 和系统目录选择窗口，在 `.native/launch-smoke/azure` 的隔离副本测试。源码版本之外不导入个人账号；原目录全部文件的 SHA-256 在每轮结束后核对不变。

1. 首次实际复现缺少两个 NeoForge 文件。
2. 自动下载校验安装器及处理器依赖，运行官方处理器成功，补齐后启动至主菜单，显示 NeoForge 21.1.265、22 个模组（含内嵌模组）。
3. 在副本中另移走 `oshi-core-6.4.10.jar` 和一个资源对象，重新点击启动自动恢复，两项恢复文件 SHA-1 均与声明一致。清单保存在 `output/playwright/launch-smoke/azure/missing-fixtures.json`。
4. 从游戏单人世界列表打开复制出的「新的世界」，核对内置服务器日志和游戏截图。仅副本产生游戏写入。
5. Rust 回归覆盖损坏 JAR 拒绝、边界拒绝、有效产物提交及已有文件保持不变；109 项通过，14 项显式集成测试忽略。前端 93 项通过，类型检查、ESLint 与 Clippy 通过。
6. 最终通过真实 EXE 的目录选择与导入接口，将原安装登记进正式游戏库：`ee2cd458-8250-4c97-bf1c-473d8d605982`，引用 `E:\minecraft`。登记时未启动原世界，未改动账号或全局设置。实际进入世界验证发生在隔离副本，画面为已载入世界的暂停菜单，内置服务器日志确认「新的世界」载入与保存。

重复主菜单测试：`$env:EASYCRAFT_AZURE_REUSE='1'; node scripts/verify-azure-launch.mjs`；同时设置 `EASYCRAFT_AZURE_WORLD=1` 会经游戏界面载入隔离副本内第一个世界。首次无 REUSE 会复制实际测试文件，不应在已有副本运行时重建。

截图、扫描报告、预检报告和运行结果：`output/playwright/launch-smoke/azure/`。处理器日志在测试数据目录 `launcher-data/repair/neoforge/21.1.265/installer-output.log`。

## 范围

本轮验证支持有官方元数据与校验值的缺失运行文件，以及 NeoForge 官方处理器补全。并非任意加载器处理器的通用安装实现；已有同大小损坏文件、无法可靠确认版本的第三方 Mod 及私有下载源不承诺自动修复。JEI 的 Minecraft 版本范围声明仍显示为建议，游戏实测可进入，不据此自动替换其文件。未验证长时间游玩或联机。
