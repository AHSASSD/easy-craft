## 1. 目标与范围

沿用此前设计：普通玩家优先，石墨灰与青绿默认主题，浅色使用相同结构；主操作易发现，高级功能按需展开。

本轮建议实现三项改进：

1. 选中游戏实例后自动后台检查依赖，并提供手动详细检查，减少启动时的重复扫描。
2. 放大启动、打开目录等高频操作的文字与点击区域。
3. 在实例概览首屏提供显眼的常用文件夹入口，方便新手。

这里的“实例”指游戏版本/整合包实例，不是某个世界存档。依赖检查不应遍历世界区块等无关大文件。

此轮不要求建立完整社区插件系统，也不要求一次实现全部加载器依赖求解与运行时故障预测。

## 3. 选中实例后自动检查

### 3.1 推荐流程

| 时机 | 行为 |
| --- | --- |
| 选中实例 | 先显示该实例已有报告及其时效，再后台核对文件清单；仅重新解析新增或修改的文件 |
| 快速切换实例 | 短暂防抖，丢弃旧实例的过期响应；避免重复排队和结果串到其他实例 |
| 安装、删除、更新、启用或禁用 Mod | 使对应报告失效，并在操作完成后合并触发一次更新 |
| 从其他应用返回 | 对当前实例做有节制的轻量核对，发现外部启动器或文件管理器造成的变化 |
| 点击“详细检查” | 强制重新读取支持范围内的全部相关声明，绕过解析缓存，方便排查缓存陈旧或文件异常 |
| 点击启动 | 轻量确认报告是否仍有效；未变化时直接复用，避免再次完整解析 |

同一实例的相同检查应合并，限制并发。后台任务支持取消时接通取消；即使任务尚不能立即停止，也必须阻止过期结果覆盖当前实例或新报告。

不要让切换“模组/截图/设置”等子页、任意任务状态更新或组件重新渲染成为完整扫描的理由。

### 3.2 缓存与性能

- 按实例、实际生效游戏目录、游戏/加载器条件及检查器版本区分报告。
- 用实际文件清单和文件属性发现新增、修改、删除、启停变化；未变化文件复用已解析元数据。
- 不要为了判断“有没有变化”在每次选择/启动时对全部 JAR 做完整哈希，否则只是把全量扫描换了形式。
- 文件时间和大小存在识别边界；手动详细检查应真实重读，不能只重复返回缓存。
- 若校验需要可靠指纹，按需计算并复用；写明缓存失效策略及其限制。
- 只读取依赖分析所需的归档条目；解析缓存应有容量/淘汰限制，不能长期保留整个 JAR 内容。
- 保留检查器已有的路径、归档大小、嵌套深度等边界，不为提速取消安全限制。

先测量冷检查、未变化复查、单文件变化复查的耗时和解析文件数；具备条件时记录内存峰值。不要未经测量宣称已经消除内存占用或达到某个加速倍数。

### 3.3 检查范围与启动行为

- 自动检查与详细检查复用真实规则。详细检查覆盖支持范围内的依赖缺失、版本条件、重复 ID、已声明冲突及可确认的环境条件。
- 不将静态检查描述为能够预测所有运行时冲突。
- 未支持的加载器、损坏/不可读文件和部分解析失败必须明确列入“未检查/未完成”；不能因为没有解析出问题就显示“全部通过”。
- 如当前校验器只能报告首个问题，准确说明其限制；不能用 UI 伪造完整问题列表。
- 检查不安装依赖、不更改现有 Mod。已有安装预检与确认流程继续保留。
- 检查进行中、发现问题或检查失败时，玩家都能选择直接/仍然启动；实际启动器必要的任务互斥和文件安全约束仍然有效。
- 保留对外部修改的轻量核对；不要把“上次通过”永久视为当前有效。

### 3.4 UI

沿用实例页现有检查条和详情面板，避免另建一套重复入口。

应能区分：尚未检查、正在检查、结果有效、文件已变化/旧报告待更新、发现问题、检查未完成。展示检查时间和检查范围。

示例文案（数量必须来自真实报告）：

> 发现 2 项依赖问题 · 刚刚检查　[查看详情] [详细检查]

> 文件发生变化，正在更新检查结果…

旧报告可继续展示，但要标记它已过期。进度有真实总量时显示数量/百分比；没有总量时使用阶段提示，不制造虚假进度。

默认开启“选中实例后自动检查”，建议提供关闭选项。初期只需这一开关与“详细检查”按钮，不必为了策略灵活性堆叠过多选项。

## 4. 提高高频操作的可读性

目的包括看清文字、容易点击和正确区分主次，不仅是放大图标。

- 启动按钮建议高约 52–56px，文字约 18px，图标配完整文字，保持最强视觉优先级。
- 打开目录等常用操作建议点击区域高约 44–48px，文字约 16px；同类按钮统一尺寸与对齐。
- 使用主题对应的清晰对比度，并保留悬停、禁用和键盘焦点状态。
- 整个按钮区域可点击，不要求准确点中图标。
- 表格、路径和次要说明继续保持紧凑，避免扩大按钮后首屏失去有效内容。
- 复用已有 UI 缩放；如提供“大字号”预设，应复用同一缩放机制，避免引入第二套冲突设置。

尺寸是设计起点，实际以正常和最小窗口、不同缩放下不截断、不遮挡为准。

## 5. 概览中的常用文件夹入口

参考用户提供的 PCL 截图中“快捷方式”的易发现性，沿用 Easy Craft 自身组件与配色，不必复制整页布局。

把现有概览快捷操作整理为显眼的“常用操作”区域，放在实例信息下方的首屏可见位置。不要简单叠加第二排重复按钮。

| 入口 | 用途说明 |
| --- | --- |
| 游戏文件夹 | 查看此实例实际使用的游戏文件 |
| 模组文件夹 | 放入或查看 Mod |
| 存档文件夹 | 查找、备份或迁移世界 |
| 截图文件夹 | 查看游戏截图 |

资源包、光影包目录可放入“更多文件夹”，避免概览塞满入口。宽窗口可采用卡片网格，窄窗口自然换行。

交互要求：

- 明确区分“管理模组”（应用内页面）与“模组文件夹”（系统文件管理器）；其他入口同理。
- 全部入口解析实际生效游戏目录，遵循当前版本隔离设置，不能硬编码 Easy Craft 托管目录。
- 共享目录显式标注“共享”，提示修改可能影响共用该目录的实例；无需每次弹出阻断确认。
- 路径不可用、文件夹未生成或系统打开失败时给出可理解反馈，不静默失败；不要仅为了展示入口而批量创建目录。
- 遵守现有目录访问边界。打开目录本身不移动、复制、删除游戏文件。
- 高级破坏性操作，例如删除实例，不放进这一组新手快捷入口。

## 6. 最小验收清单

### 依赖检查

- 选中实例会自动检查；快速切换时没有结果串位或重复任务堆积。
- 未变化复查复用解析结果；增加、修改、删除和启停文件能正确使缓存失效。
- 外部修改、切换实际游戏目录、版本隔离变化与加载器条件变化会被正确处理。
- 手动详细检查真实重读文件；失败、部分支持和过期状态准确展示。
- 点击启动不会无条件重复完整扫描；检查中的“直接启动”和问题后的“仍然启动”可用。
- 检查取消、不可读文件、损坏 JAR、长路径与空模组目录均有合理结果。
- 记录实际性能结果，并区分测试夹具与真实实例；不以合成数据结果冒充用户大型整合包表现。

### UI 与目录

- 检查深浅主题、1120×720 普通窗口、项目最小窗口，以及 125%/150% 缩放。
- 启动和目录操作文字清晰，无重叠、截断与横向溢出；键盘焦点和菜单关闭正常。
- 概览能快速找到常用文件夹；在托管实例、本地引用实例、独立目录、共享目录中打开正确位置。
- 不存在或无权限目录有明确反馈，不改写源目录或个人存档。

运行项目相关类型检查、构建及必要回归测试。保存实际桌面截图、测试摘要和可运行程序路径；说明仍未支持的检查范围。
