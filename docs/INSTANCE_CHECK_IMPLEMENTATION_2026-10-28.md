# 实例检查与常用操作实施记录

日期：2026-10-28（北京时间）。依据交接文档实施，保留已有实例子页和启动能力。

## 查明的问题与修复

原 Fabric 检查器在遇到首个依赖问题后返回。回归夹具同时声明两个缺失前置和一个冲突，旧实现只报告第一个缺失；现在汇总该候选方案下支持范围内的多个问题，安装预检同步复用。原先 Forge/NeoForge 实例直接返回“未支持”，现增加 TOML 声明检查。未知/损坏文件和求解失败进入未完成范围，UI 不再仅因问题数组为空显示通过。

`mod_check.rs` 为已安装模组提供只读分析：Fabric 声明复用既有版本、别名、内嵌候选和依赖规则；Forge/NeoForge 读取对应 TOML、必需/可选依赖、客户端适用条件、数字 Maven 版本范围、重复 ID 与声明的不兼容关系。读取 Jar-in-Jar 清单内的模组，避免把确已内嵌的前置一概当作缺失。没有解析器支持的兼容桥接、语言加载器、动态服务和复杂版本候选明确列出。

原生分析释放宿主任务/状态锁后执行，另用检查缓存锁限制分析并发，检查不会占用游戏任务槽。前端在选中实例后防抖 220 ms；同上下文请求合并，串行执行，排队的过时自动请求在开始前跳过，已开始的检查仍可能执行到结束。响应有实例及上下文保护，旧响应不能覆盖新报告。

切换实例子标签不再触发检查；Mod 启停、内容导入及资源提交会更新相关时效，返回应用时至少间隔 5 秒复核，启动前轻量核对。可在启动设置关闭选中后的自动检查；详细检查强制重读。检查期间及发现问题后分别保留“直接启动”“仍然启动”，实际启动任务互斥仍有效。

## 缓存边界

- 进程内缓存，重启/更新程序后自然失效。声明按实际路径、加载器解析类型、大小、修改时间和创建时间复用；报告另按实例、实际游戏目录、游戏/加载器条件和 Java 要求区分。
- 每次轻量核对仍枚举当前 mods 目录并检查属性，识别增加、移除、修改和启停；不扫描存档区块，不为发现变化而完整哈希所有 JAR。
- 解析缓存最多 1024 个条目，序列化声明预算 16 MiB；报告最多 8 项，加载器锁定记录最多 16 项。这些不是进程实际内存峰值承诺，结构及临时解压另有开销。
- Fabric 加载器锁定资料首次读取/变化/详细检查时验证，属性未变时复用。保留归档条目、文件大小、声明大小、嵌套深度、展开量、候选组合和条件数量边界。
- 时间与大小不能识别所有刻意保留属性的内容替换；详细检查绕过缓存真实重读。后台检查并非原子文件系统快照，检测到读取期间变化会标为未完成。没有实现操作系统实时监控或即时取消已经开始的原生解析。

## 概览与目录

概览首先显示“常用操作”，提供游戏、模组、存档、截图四个文件夹；资源包/光影包在更多文件夹中。应用内管理入口独立标明，避免和文件管理器入口混淆。目录按照宿主当前实际生效路径解析，区分共享与独立范围；缺失/不可用返回反馈，不为了展示入口创建空目录。新增受控 `openFolder` 服务，不允许任意路径。

启动按钮约 54px 高、18px 字；文件夹卡片标题 16px，子页目录操作也提升点击尺寸，沿用既有主题、缩放和焦点状态。
