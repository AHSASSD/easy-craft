# 实例重命名与移除

实例列表新增常驻“…”管理按钮，原右键菜单与封面的管理入口继续可用。聚焦实例行后，F2 打开重命名，Delete 打开移除确认，不直接删除。

重命名沿用原生校验与原子保存：1–60 个可见字符，只改显示名称，不重命名版本 ID、游戏目录、JAR 或存档。

移除提供两种明确操作：

- 只移出游戏库：保留原文件。引用的本地安装只允许此操作。
- 自有实例文件夹可移入数据目录下 `instance-trash/{UUID}`，该目录是启动器自己的回收区，不是 Windows 回收站。文件可手动找回，空间不会立即释放；本轮未提供自动清空或恢复实例的 UI。共享 libraries、assets 和共享游戏目录保留。

宿主再次验证 ID、任务/登录状态、当前磁盘清单、目录所有权和其他实例是否使用该目录。路径检查拒绝重解析链接；目录整体移动，不递归追踪链接或删除文件。目标唯一且不覆盖。先提交移除后的清单，再移动自有目录；移动失败时恢复清单。中断可能保留未登记的原目录，不会删除其文件。双重失败明确提示当前已移除且原文件保留，并同步内存状态。

`NativeService.removeInstance(id, archive)` 对应 `native_instance_remove`，返回回收区路径或 null；无论操作成功与否，前端重新读取实际游戏库。移除当前实例后选择下一实例，空库回到安装引导。

验证：Rust 108 项、前端 92 项、浏览器 E2E 14 项通过；类型检查、ESLint、Clippy、桌面构建通过。真实桌面测试仅使用隔离合成夹具，覆盖“…”菜单、F2 修改并保存、Esc 取消、Delete 确认、移入回收区后内容不变、引用源文件保留，以及重新载入后的空库。原生回归还覆盖任务互斥和 Windows 文件占用导致的移动失败回滚。没有对个人版本执行移除。
