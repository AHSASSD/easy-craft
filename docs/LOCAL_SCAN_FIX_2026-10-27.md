# 真实 C 盘扫描复测、完成状态修复与结果界面

后续已改为默认直接添加原安装，并支持已安装 Forge/NeoForge 启动；本轮行为、性能与实际主菜单测试见 [后续实施记录](LOCAL_REFERENCE_FORGE_2026-10-27.md)。本文是前一阶段记录。

本轮依据用户报告“选择 C 盘 .minecraft 后显示完成，游戏库仍为空”，以及后续扫描速度和结果 UI 要求实施。参考本机真实 `%APPDATA%/.minecraft`，只读扫描；没有往用户正式游戏库导入测试数据，也没有修改原 Minecraft 内容、账号或启动游戏。

## 复现与定位

- 原真实目录扫描运行 164.3 秒仍未结束，停止的是本轮独立诊断进程。记录：`output/playwright/local-scan/user-before-timeout.json`。
- 旧扫描会递归索引整个游戏内容树；一个超过大小限制的世界区域文件还会导致版本候选不可导入。新增回归测试在旧实现中失败，证明问题不只是 UI 慢。
- 原生扫描完成使用通用“任务完成”，任务日志没有结果；前端也把确认按钮放在全部版本大卡片之后。扫描面板一旦关闭，候选列表丢失，用户很难确认是否执行过真正导入。
- 另一个读取瓶颈：对本地 File 直接使用 `serde_json::from_reader`，没有缓冲，造成逐字节系统读取。真实目录在仅拆除递归索引后约 25.34 秒；只加入 BufReader 后降至约 3.83 秒。JAR 中央目录与内置版本信息仍检查，没有用空壳数据伪装扫描完成。

## 当前扫描范围

- 只枚举版本目录、读取版本 JSON/JAR、解析基础版本及加载器继承；定位 libraries/assets，识别已知 mods/config/saves/resourcepacks/shaderpacks 等入口。
- 只看 saves 的直接子目录及 level.dat/level.dat_old 标记，最多检查 1000 项，不展开 region 或其他世界数据。实际例子中识别到 19 个带标记的存档目录；这不是 19 个已通过完整 NBT/运行验证的世界。
- 相同游戏目录的入口摘要在本轮扫描中复用。未知游戏文件总数和大小明确显示“确认导入后检查”，不显示虚假的 0 个内容文件或全面通过。
- 确认导入后再建立逐文件索引、计算校验和、检查复制大小限制并执行事务复制；前后复核版本元数据、入口状态及复制时文件快照。扫描阶段不是所有世界文件的内容快照。
- 原有路径边界、链接拒绝、账号配置排除、取消、官方资源验证和失败回滚保留。正式导入仍受单文件 512 MiB、每实例内容 2 GiB 等现有限制；快速识别为可导入不代表尚未检查的所有游戏内容一定能复制。

## 状态与界面

- 扫描完成显示“扫描完成，尚未导入”，包含发现、可导入、异常和重复数量，日志记录来源与每个候选原因。日志条数遵守 IPC 的 200 条边界。
- 底部和任务日志增加查看扫描结果入口，关闭面板后可恢复本次候选。仍需明确选择版本、检查范围并确认导入，不会扫描后擅自添加几十个实例。
- 真正导入成功单独显示“已成功导入 N 个本地版本，游戏库已更新”；失败会写入具体错误日志。
- 结果 UI 改为石墨灰与青绿的紧凑窗口：顶部统计、状态筛选与名称搜索，中间独立滚动列表，底部固定选择与确认区。
- 每行显示真实版本名、加载器、目录隔离状态、存档目录数及状态标签；问题摘要清晰显示，完整来源、警告及实例重命名按需展开。筛选或搜索不会丢失已选版本。
- 小高度下收起大数字统计，仍在筛选按钮保留数量，为列表和底部操作留出空间。浅色主题沿用同一套组件和层级。

## 本机真实结果

桌面 EXE 经真实系统文件夹窗口选择用户目录，重复扫描约 4.6–5.3 秒（包含目录选择自动化耗时），读取结果稳定为 63 个候选：

| 分类                            | 数量 | 依据                         |
| ------------------------------- | ---: | ---------------------------- |
| 可继续确认导入                  |   11 | 当前支持的版本结构及基础 JAR |
| 缺少基础 JAR                    |   28 | 实际预期 JAR 文件不存在      |
| Forge/NeoForge 尚不支持运行导入 |   23 | 实际启动主类/依赖声明        |
| 无法确定唯一版本 JSON           |    1 | 找不到唯一有效元数据         |

没有把这 11 个候选说成已经导入。测试确认正式确认前游戏库仍为 0，恢复面板后可批选 11 个，未经范围确认的导入按钮保持禁用。原版与 Fabric 实际导入能力另外使用隔离真实资源结构复验。

扫描前后比对了 119 个版本 JSON 和游戏设置文件的 SHA-256、大小与修改时间，保持一致。没有读取原启动器账号令牌文件。

## 验证与复现

- `scripts/native.ps1 -Action test`：新增完成状态和不递归世界文件的有效回归，91 项通过，9 项需显式开启的集成测试未包含在常规运行中。
- `npm test -- --reporter=dot`：83 项通过，覆盖恢复扫描、明确确认、搜索与选择状态等。
- `npm run test:e2e`：14 项通过。
- `scripts/verify-real-local-scan.mjs`：启动独立数据目录的真实桌面 EXE，经系统文件夹窗口只读扫描实际 C 盘目录，验证结果、筛选/搜索、恢复、日志、固定操作区、最小窗口及 125% 缩放、浅色主题。只允许选明确的 Roaming/.minecraft，不放开任意外部路径自动化。
- `scripts/verify-local-import.mjs`：在隔离目录复验原版/Fabric 的真实扫描、取消、确认导入、入库、复制及重复处理；没有启动 Minecraft。
- 原生只读诊断：显式设置 `EASYCRAFT_READONLY_SCAN_ROOT`，执行 `scripts/native.ps1 -Action test -Integration scan-diagnostics`。结果写到 `output/playwright/local-scan/user-diagnostic.json`。
- 桌面截图与结构化记录：`output/playwright/local-scan/desktop/`；导入复验：`output/playwright/local-import/`。
- 125% 缩放下 WebView 的 CDP 截图存在裁切，另外对自建测试窗口做原生像素截图 `05-minimum-125percent-window.png`，确认 800×540 窗口的列表和确认按钮均在可见范围；常规窗口和浅色截图使用 CDP 正常输出。
- 实际导入后的启动准备复验：原版 71 项、Fabric 79 项 classpath 文件均可定位，独立/共享 gameDir 参数正确；只准备命令，没有执行 Minecraft。

产物：`src-tauri/target/debug/easy-craft.exe`。类型检查、构建、ESLint、Clippy 和格式检查按本轮改动执行。性能数字来自本机这一个实际目录，不保证其他磁盘/目录耗时相同。
