# 第二轮：提前显示可操作版本

## 改动

上轮连接复用、gzip 和浏览缓存继续使用。本轮解决首次打开详情必须等待全部历史版本的问题。

- Modrinth 详情同时请求「当前游戏版本」和「完整历史列表」，先成功的一份先显示。完整列表缓存已热时，也能直接胜出。相同的项目信息请求仍由后端缓存合并。
- 当前版本先到时，可立即选择版本、文件和生成安装预览，历史列表在后台补齐。后台加载状态独立于安装操作，不会持续禁用控件。
- 补齐列表保留已选版本、文件和安装预览；历史列表失败单独提示并可重试，已加载内容仍可使用。
- 返回列表、打开另一项目和卸载页面会使旧的后台结果失效。两份请求都失败才将详情整体显示为失败。
- CurseForge 仍只发原来的一份详情请求，避免其不支持当前版本过滤时重复下载。
- 资源页的正式游戏版本下拉清单在 NativeService 内缓存五分钟，同一时刻多个调用合并。缓存返回副本、失败可重试、服务停止清空。手动刷新官方完整版本清单和实际安装校验仍走原来的独立请求路径。

没有新增依赖。没有修改 450ms 的输入防抖来掩盖网络延迟，也没有引入默认第三方镜像。完整版本列表仍会下载；优化目标是提前可操作，额外增加一次较小的过滤请求，并非减少所有场景下的总流量。

## 实测

真实 debug EXE + 隔离空游戏库 + WebView2 CDP，Fabric API，Minecraft 1.21.1。每次重启被测进程，首次点击之前不预热详情。API/CDN 的服务器端缓存不在本地控制范围内。

| 记录                                        | 首次可操作 | 历史完整就绪 | 首次显示内容                       |
| ------------------------------------------- | ---------- | ------------ | ---------------------------------- |
| 本轮改动前 `baseline-next.json`             | 3932 ms    | 4027 ms      | 1216 个版本，12 个分组             |
| 改动后 `progressive.json`                   | 2388 ms    | 18843 ms     | 当前游戏版本的 36 个文件，1 个分组 |
| 改动后最终完整验证 `progressive-final.json` | 856 ms     | 1764 ms      | 当前游戏版本的 36 个文件，1 个分组 |

两次改动后最终均补齐 1216 个版本、12 个分组，展开的 Minecraft 1.21 分组为 169 个版本。`progressive-final.json` 记录缓存再次打开首屏 32、44 ms，完整列表就绪 83、87 ms。

这些是少量真实网络样本，不是稳定性能承诺。完整列表有一轮仍需 18.8 秒，说明国际网络或服务端等待依然存在；这一轮玩家可以在约 2.4 秒后操作当前版本。不能宣称本轮让全量下载在所有情况下都更快。

测试脚本曾有两个断言需要适配：原断言要求首屏已经有全部分组，不适用于渐进加载；尝试统计原生调用的页面脚本未能拦截调用，不将其零计数当作真实请求次数。最终脚本移除这段无效拦截，改为验证三次资源页挂载后下拉清单仍可用；请求合并次数在 NativeService 的确定性测试中验证。`progressive-isolated.json` 为该次未通过计数断言的中间记录，不作为最终完整验证结果。

## 验证

- 先补充回归测试，确认旧实现的两个问题：历史列表不返回就无法选择当前版本；三次版本清单调用触发三次原生请求。然后实施改动并通过测试。
- `npm test`：78 项通过，新增覆盖提前选择、后台补齐保留版本和文件、历史失败/重试、迟到结果、完整缓存先到、公共清单并发合并/过期/无效响应重试/返回副本/停止服务。
- `npm run test:e2e`：14 项通过。
- `npm run lint`、`npm run format:check`、构建内 TypeScript 检查通过。
- `node scripts/benchmark-modrinth.mjs progressive-final --cold-ui`：真实桌面首屏/完整列表/缓存重复访问计时、大版本完整性、切换资源页、下拉选项和截图通过。
- `node scripts/verify-mod-preflight.mjs`：隔离实例的缺失依赖、风险确认、完整依赖、实例变化、缓存篡改、损坏 JAR，及真实 FerriteCore 在线预检/安装/磁盘 SHA-512 校验通过。
- `scripts/native.ps1 -Action build`：已构建 `src-tauri/target/debug/easy-craft.exe`。本轮未改 Rust 运行逻辑。

后续如果要改善国际网络等待，可单独评估用户可选的元数据镜像或跨启动 HTTP 条件缓存；需要同时处理来源可信度、更新时效、回退和刷新语义，不能将它们当作已经实现的能力。
