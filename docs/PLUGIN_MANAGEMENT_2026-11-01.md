# 插件管理：实施与边界

本轮把原有三类手风琴侧栏和本地外观 JSON 导入，扩展为原生存储、启停、按实例授权、兼容与依赖检查、更新事务、系统回收站和恢复模式。保留原工作区修改；没有操作玩家账号、存档或现有游戏文件。没有安装新的运行时依赖或搭建服务。

## 已实现的功能链路

- 三类标题顺序固定，默认展开“我的工具”，最多展开一类，允许全收起；切分类不关闭右侧工具。下载与本地导入固定在底部。内部五个启动器基础模块不进入插件列表。
- 系统文件选择与拖入共用原生检查和安装事务。取消选文件不创建记录；重复包不重复安装。非 JSON、损坏、过大、未知字段、脚本或不兼容接口给出明确错误。浏览器预览拒绝安装和删除。
- 安装和启用分开。侧栏与右侧区分已安装、停用、启用、正在运行、异常、恢复模式。工具仅在点击运行时执行，不常驻后台。
- 安装包统一位于 `dataRoot/plugins/packages/<id>/<UUID>.json`，安装记录与配置位于 `plugins/registry.json`。记录使用相对路径，复制整个数据目录可迁移。外观偏好继续由原偏好服务管理，激活状态以原生注册表为准。
- 原浏览器 `easycraft.local-plugins.v1` 记录自动迁移；原记录在全部迁移成功后才移除。旧包转换为声明式格式，初次迁移不会擅自启用或重置现有外观。
- 主题与布局分别占用 `theme`、`layout` 独占位置，可以搭配。切换同位置插件先停用旧插件并验证整套启用关系，通过后原子提交；冲突、依赖或写盘失败保留原状态。停用外观恢复接管该位置之前的偏好。
- 按精确版本或 `*` 检查插件依赖，检测循环、缺失与版本不匹配；双向核对明确冲突。依赖方尚在启用时拒绝单独停用它的依赖。删除时列出直接依赖方，确认后同时停用所有受影响的间接依赖方。
- 实例扩展在“生效实例”内单独勾选；入口仅在被授权的实例出现。启用和实际运行均核对 Minecraft、加载器条件。实例入口的显示、固定、顺序配置持久保存。
- 工具输入、结果和检查报告在本次启动器进程内跨工具/页面切换保留。它们不会写进游戏目录，关闭启动器后不会自动持久保存输入文本。
- 插件安装、配置、启停与实际工具任务共用宿主底部任务、阶段计数、取消与错误日志。JSON 工具按解析/格式化两步计数；实例检查复用既有增量缓存。取消检查可丢弃结果，但不会立刻中断已在执行的一次归档解析。

本轮沿用宿主现有单任务互斥：游戏或其他安装任务运行时不会另起插件任务，也不会替玩家中断当前任务。多个工具可以保持启用，任务不等于启用状态。

## 当前可用的宿主能力

这些是由宿主实现并限制范围的真实功能；插件包只声明选择、配置和入口，不能提供自己的代码。

| 能力                 | 作用范围 | 权限             | 允许入口                             |
| -------------------- | -------- | ---------------- | ------------------------------------ |
| `tool.json`          | 全局     | 无额外权限       | `tool` 工作区                        |
| `instance.mod-check` | 按实例   | `instances.read` | `instance-overview` / `instance-tab` |
| `appearance.theme`   | 全局     | `appearance`     | `appearance`                         |
| `appearance.layout`  | 全局     | `appearance`     | `appearance`                         |

`instance.mod-check` 只提供模组声明检查，不安装或修改 Mod，也不能读取账号令牌。它不等于游戏必然可启动或所有运行时冲突均已检查。JSON 工具仅处理最多 1 MiB 的本地输入，没有联网行为。

示例包可从扩展的“本地导入”选择：

- [JSON 工具](plugins/json-tools.ecplugin.json)
- [实例模组检查](plugins/instance-check.ecplugin.json)
- [旧格式布局包](plugins/compact.ecplugin.json)

示例不会自动加入玩家的插件列表。作者字段是包内声明，不是官方认证；`official.*` 仍为内部模块保留，不能借作者名称获得额外权限。

## 声明契约

声明 `schemaVersion: 2`，宿主接口 `apiVersion: "1.0.0"`，配置格式 `configVersion: 1`。需要标识、名称、作者、版本、简介、图标、主要分类、能力、入口、作用范围和权限；支持 `minecraft`、`loaders`、`dependencies`、`conflicts`、`exclusiveSlots`、`settings`、`updateSource`。完整可导入样例见上方文件。

- 一个主要分类；可以有多项能力与多个合法入口，只在左侧列一次。当前按实例和全局能力不能混在同一个包内启用，避免隐式扩大实例授权范围。
- 图标只能选择宿主的 `code/shield/layout/theme/palette/wrench/boxes`。没有任意图片、SVG、CSS、HTML 或脚本注入。
- Minecraft 条件为精确版本列表；加载器为合法类型列表；插件依赖支持精确三段版本或 `*`，暂不支持 SemVer 范围。
- 权限与能力严格对应；多报、漏报、未知权限均拒绝。没有联网、任意文件写入、外部进程或游戏组件安装权限。
- 外观设置仅接受主题、十六进制强调色、工作区类型和 240–420 侧栏宽度。JSON 工具支持 2/4 空格缩进配置。未知配置拒绝。
- 每包最大 128 KiB，最多 100 个已安装包；最多保留 500 个插件的历史设置。超限提示，不自动清掉用户数据。
- `updateSource` 仅记录不带凭据的 HTTPS 地址，当前不获取更新。没有可用插件市场，也没有下载或“检查更新成功”的占位按钮。

## 更新、删除与恢复

本地重导入同 ID 的不同声明时，展示版本、作者与权限变化并确认。原生层再次核对旧包 SHA-512，避免确认期间记录已变化。新包先写到新文件，配置兼容、依赖与启用关系通过后，原子替换安装记录。写盘或校验失败清理未提交候选，旧包继续可用；已有配置与成果保留。历史成功版本文件仍保存在受管目录，不自动永久清除。在线同名替换、联网更新、签名验证未开放。

快捷删除使用 Windows `IFileOperation` 的 `FOFX_RECYCLEONDELETE`，遇错停止；操作失败保留包与记录，不调用永久删除作为兜底。成功后右侧提示“某某插件已进入回收站”。只回收当前受管包文件，不删除设置，也不连带删除报告、导出、备份或游戏数据。回收后的注册表提交使用持久日志，避免系统回收成功而写记录失败时丢失管理状态。Windows 参数依据 [Microsoft IFileOperation 文档](https://learn.microsoft.com/zh-cn/windows/win32/api/shobjidl_core/nf-shobjidl_core-ifileoperation-setoperationflags)。

扩展页始终提供“停用第三方插件”。恢复模式阻止第三方外观与工具生效，保留记录；基础导航、账号、游戏库仍由宿主管理。即使注册表损坏，启动器仍能进入并报告错误，原文件不重置。也可在数据目录创建 `plugins/disabled`，或用 `EASYCRAFT_DISABLE_PLUGINS=1` 启动进行恢复；环境变量开启时需移除该变量并重启才能退出。

包文件缺失、校验不符和目录暂不可用不会删除记录。当前会话中目录失联保留侧栏缓存并禁止使用；刷新或回到窗口后重新核对。无法读取整个数据盘时会提示连接数据盘，不把它描述为包已损坏。

## 可执行插件的具体建议，待确认后再实施

建议采用**独立插件宿主进程中的 WASM 运行环境**，不要把外部 JS 装入当前 WebView，也不要把官方内部 `PluginContext` 原样交给社区包。

1. 默认不给 WASI 文件系统、网络与进程接口；设置内存、指令预算与超时，插件崩溃只终止自己的任务。
2. 仅通过宿主 RPC 请求命名能力。请求绑定插件身份、任务和实例授权；返回结果经过大小与结构验证，不传账号对象或令牌。
3. 工具界面优先采用宿主组件声明，不能修改全局样式或覆盖启动、账号和恢复按钮。
4. 新增网络能力时按明确域名授权；文件能力限定插件成果目录和玩家批准的实例范围。权限增加须重新确认，实例授权不能自动扩散。
5. 需要游戏组件时，先产生可审查的文件变更计划，核对游戏/加载器条件、文件归属与哈希，通过现有安装事务提交。卸载只处理插件拥有的文件。
6. 下载源与更新应包含固定发布者身份、版本、来源与文件哈希；更新事务不跨来源覆盖本地包。签名与发布者身份机制确定后才接入市场。

本轮未选择 WASM 库、未执行外部程序，也没有实现任意社区功能的运行 SDK。仍需确认宿主运行环境、工具组件协议、组件安装权限及发布者身份/下载源。

## 验证

验证脚本：`scripts/verify-plugins-ui.mjs`，使用独立 `.native/plugins-ui/<UUID>` 数据目录与独立 WebView 数据；两份空目录实例是合成夹具，不是实际游戏启动测试。

已跑通桌面文件选择、拖拽、取消选文件、真实 JSON 格式化、工具切换保留输入/结果、按实例启用、两种实例入口、只读检查、外观搭配、重复/可执行字段拒绝、本地更新、恢复模式、普通/最小窗口、减少动画、真实 Windows 回收站、配置与成果保留。

回归测试覆盖依赖循环/缺失/冲突、独占切换、写盘失败回滚、取消、损坏包、目录不可用和回收失败不永久删除。前端另外验证偏好恢复、断盘保留列表与异步结果不覆盖新输入。最终检查日志位于 `output/plugin-management-*.log`；桌面截图与逐项结果位于 `output/playwright/plugins/<UUID>`。

最终结果：

- TypeScript、ESLint、Rust check、Clippy 均通过；前端 103 项、后端 139 项、浏览器端到端 14 项通过。后端默认跳过 18 项集成测试，其中系统回收站测试已另行显式执行并通过。
- 桌面实测 21 个检查点通过，额外验证缺依赖更新失败后旧版仍启用；删除后从系统回收站实际查得原包文件，而不仅是确认文件已从源目录消失。
- 截图与报告：`output/playwright/plugins/7099ac5f-23d3-423d-aa51-cd90c0cf55f0/`；包含暗色工具、浅色外观、800×540 最小窗口和实例检查界面。
- 可运行程序：`src-tauri/target/debug/easy-craft.exe`。现有账号与个人游戏目录没有用于本轮测试。
