# Easy Craft：双栏导航、内容与功能实现方案

2026-10-23 · 基于 V0.3.1 现有代码、用户手绘草图与参考图。本文是下一轮实现方案，不代表文中规划功能已经完成。正式开发以本次用户提出的“三入口、联动左栏”优先；旧 V0.1 规格保留作历史依据。

## 1. 产品决定

**左上三个固定入口：游戏库（方块）→ 设置（齿轮）→ 下载（向下箭头）。选择入口后，左栏中部换成对应列表；右侧显示该列表选中项的内容。账户固定在左下，任务入口固定在底部。**

用户说的方块“存档”入口，这里按草图的“已下载 MC 版本名字”实现为游戏库。一个安装版本对应一个独立实例，里面可以有多个世界存档；实际世界列表放在实例右侧的“存档”页，避免把版本和世界混成同一级。允许两个相同游戏版本的实例有不同名称、Mod 和存档。

此轮先设计，不修改现有应用和用户数据。交互预览使用明确标注的示例数据，只演示导航，不执行下载、登录、启动或文件写入。

## 2. 参考研究与取舍

参考依据详见 [源码与官方资料调研](UI_REFERENCE_RESEARCH.md)。PCL 学习“主入口切换后使用对应左侧分类”和卡片分组；HMCL 学习账户身份、实例管理、下载资源及设置分组的边界。采用相同的易懂规律，保留 Easy Craft 自己的双栏结构、图标和素材。

[HMCL 官方界面说明](https://docs.hmcl.net/launcher/gui-features.html)把设置中的全局游戏、Java、外观与下载等分开；这支持我们把现在集中在下载页的 Java 配置移回设置。具体导航细节以本地源码和官方资料为参考，不宣称与其他启动器最新发行版逐像素一致。

| 学习点                 | Easy Craft 的处理                                  |
| ---------------------- | -------------------------------------------------- |
| 页面有稳定的导航骨架   | 三个入口位置始终不动，左栏内容切换                 |
| 游戏选择与内容管理分层 | 左侧选实例，右侧再选 Mod / 存档等标签              |
| 普通设置与高级设置分组 | 常用参数直接可见，高级参数折叠，不显示大段技术说明 |
| 下载任务独立于当前页面 | 切换页面不取消任务，全局底部显示真实状态           |
| 背景和主题可定制       | 图片用于游戏页横幅，设置表单使用稳定背景           |
| 高密度菜单与复杂操作   | 不照搬；第一屏只保留常用动作，其他放右键或“更多”   |

## 3. 窗口与信息架构

默认 1120×720，最小 800×540；保留原窗口设置。标题栏高度 44–48px，左栏默认 280–300px，可拖动至 240–420px；右侧占剩余宽度。在最小窗口右侧内容变为单列，允许纵向滚动，不压成横向溢出的多列卡片。可折叠左栏时必须保留一个可见的展开按钮。

```text
┌ Easy Craft ──────────────────────────────── ─ □ × ┐
│  [▣ 游戏库] [⚙ 设置] [↓ 下载]  │ 当前位置 / 当前内容 │
│─────────────────────────────│─────────────────────│
│ 随入口变化的列表             │                     │
│                             │ 选中项详情           │
│ 游戏库：已安装实例            │ 列表 / 表单 / 管理区  │
│ 设置：启动、个性化、其他…      │                     │
│ 下载：原版、Mod、光影…        │                     │
│                             │                     │
│ 搜索 / 新建 / 导入等上下文动作 │ 页面主要操作         │
│─────────────────────────────│─────────────────────│
│ [皮肤头像] 玩家名 ▾           │ 任务摘要 / 查看任务   │
└─────────────────────────────┴─────────────────────┘
```

三个入口位于左框顶部，不再额外放“账户”作为第四个同级入口。标题栏只放品牌和窗口按钮，页面内部显示面包屑；全局任务入口不挤进主导航。

| 主入口 | 左栏中部                                       | 右侧                                | 首次默认选中                               |
| ------ | ---------------------------------------------- | ----------------------------------- | ------------------------------------------ |
| 游戏库 | 已安装实例、搜索、新建/导入                    | 当前实例的概览、内容与配置          | 上次有效实例；否则第一个；空库展示安装引导 |
| 设置   | 启动、个性化、下载设置、其他                   | 对应全局设置表单                    | 启动                                       |
| 下载   | 原版游戏、模组、光影包、整合包、数据包、资源包 | 搜索/筛选、资源详情、安装目标与进度 | 原版游戏                                   |

“下载设置”控制连接等偏好；“下载”入口负责获取内容。文案上明确“下载设置”，不要在两个地方都叫“下载中心”。

每个入口记住自己的选中项、搜索与滚动位置。例如：游戏库 → 生存实例 → 存档，切换设置调整内存，再回游戏库，仍停在该实例的存档页。用户主动选择另一个实例时默认进入该实例上次访问的标签；未访问过时进入概览。

## 4. 游戏库：页面内容

### 左栏

- 标题“我的游戏”，旁边“+”新建和“⋯”更多；刷新放更多中，避免三个小按钮挤在一起。
- 实例行：44px 方块图标、名称、游戏版本、加载器。显示必要状态：准备就绪 / 运行中 / 需修复。未知状态不伪装为“可用”。
- 单击选择，右键弹出上下文菜单；双击启动默认关闭，可在设置开启。键盘 Enter 激活，菜单可用 Escape 关闭。
- 搜索仅搜索实例名、版本和加载器；无结果提供清除搜索，空库提供“安装游戏”和“导入整合包”。
- 列表底部可有小型 ZIP/MRPACK 拖放区，说明当前版本实际支持的能力。阶段一仍写“检查内容”，安装服务通过验收后才改为“导入安装”。

### 右侧概览

横幅高约 180–220px，显示实例名、游戏版本、加载器、Java 条件和一个主“启动游戏”按钮。当前引用图中大面积横幅可用于概览；其他管理页缩为 64–88px 的标题区，给内容留空间。

概览下方只显示实用信息：实例说明、启动环境、最近一次启动结果、打开目录/设置等快捷操作。启动次数、占用空间、截图数量只有真实收集后才展示；不预填漂亮数字。实例说明没有内容就提供简短编辑引导，不生成虚构介绍。

| 右侧标签   | 内容与操作                                  | 当前基础 / 待实现                                              |
| ---------- | ------------------------------------------- | -------------------------------------------------------------- |
| 概览       | 横幅、身份、启动、环境、最近任务            | 已有真实启动与部分信息；统计/描述需补原生字段                  |
| 模组       | 本地列表、搜索、启停、打开文件夹、获取模组  | 待实现目录扫描、元数据与安全启停；文件读取失败按“未知文件”显示 |
| 资源与光影 | 资源包 / 光影包子分组、本地导入、获取资源   | 待实现；保存到目录不等于在游戏中已启用                         |
| 存档       | 世界列表、难度/规则/时间/天气、数据包入口   | 已有配置编辑；拆分列表和编辑区，补备份恢复与新布局支持         |
| 截图       | 真实 screenshots 目录缩略图、查看、打开目录 | 待实现；目录为空就展示空态                                     |
| 实例设置   | 该实例参数与音画选项，显示继承关系          | 音画已实现；Java/内存的实例覆盖待实现                          |

首个导航重构版本只开放已有真实能力的标签。规划标签可出现在设计稿，在软件里不得出现“点击后空白”的可用按钮。日志通过任务抽屉进入，不必再占一个常驻标签；更新日志仅在有真实内容时显示。

右键实例菜单规划：启动、重命名、打开目录、导出/复制、删除。其中重命名只改显示名称，不移动磁盘目录；复制/导出必须真实复制对应文件后才显示成功；删除显示完整目标和是否保留备份，移入可恢复位置并要求明确确认。阶段一尚未具备的操作隐藏或解释性禁用，不能复用演示菜单假装修改真实实例。

## 5. 设置：分类、作用范围与保存

| 左栏分类 | 右侧分组                                                                     | 生效方式                                           |
| -------- | ---------------------------------------------------------------------------- | -------------------------------------------------- |
| 启动     | Java 路径/检测、自动/手动内存、可选内存整理、启动行为、高级 JVM 参数（后续） | 影响之后的启动；不修改正在运行的游戏               |
| 个性化   | 草方块亮色 / 深板岩暗色、强调色、背景、背景遮罩、界面缩放、减少动态效果      | 主题即时预览；仅已实现的偏好可持久化，其他逐步补齐 |
| 下载设置 | 并发/重试（待可配置）、缓存位置与大小、缓存检查/清理、来源说明               | 下一个任务开始生效；清理不得删除存档/已安装 Mod    |
| 其他     | 关于/版本、日志与诊断、帮助、演示与开发入口、数据位置                        | 具体操作有独立反馈，不提供“一键重置所有数据”       |

Java 检测从当前 NativeWorkspace 的“运行配置”移至“设置 → 启动”；原版下载页只显示需要的 Java 版本摘要和“前往设置”。内存页复用 MemoryPanel，不另外做一套分配逻辑。账号不进入设置分类，仍从左下入口打开。

**全局与实例的区别：** 设置入口编辑全局默认值，实例右侧“实例设置”编辑覆盖值。覆盖未实现前，明确写“当前为全局默认，所有实例共用”，不提供无效的“仅此实例”开关。实现时仅保存用户显式覆盖项，恢复继承则删除覆盖项；启动解析顺序为实例覆盖 → 全局设置 → 程序默认值。内存、Java 参数按真实版本条件验证，界面展示“本次使用”的最终值。

保存规则：主题等即时偏好直接保存并短暂提示；Java/内存等表单有明确“保存”按钮和未保存标记，切页有未保存时提供保存/放弃/继续编辑；世界配置保留独立保存与备份。保存失败保留输入内容，不显示成功勾号。

## 6. 下载：六类内容与目标

下载页没有大景观横幅。右侧顶部为分类名、搜索、来源和筛选；需要目标时，显著显示“安装到：实例名 · 版本 · 加载器”。浏览资源无需先选实例，但实际安装必须选择有效目标。

| 分类     | 右侧展示                                                                     | 安装目标                         | 完成判据                                                         |
| -------- | ---------------------------------------------------------------------------- | -------------------------------- | ---------------------------------------------------------------- |
| 原版游戏 | 正式版；快照/历史版需筛选显式开启。选择版本后进入命名、加载器、Java 条件摘要 | 新建独立实例                     | 资源校验、清单提交成功后加入左侧游戏库                           |
| 模组     | 搜索、游戏版本/加载器/环境筛选、详情和版本、必需依赖                         | 已有兼容实例的 mods/             | 所选文件和必需依赖校验并提交；记录来源/版本                      |
| 光影包   | 搜索、版本、渲染器要求、预览/说明                                            | 实例 shaderpacks/                | 文件提交；提示是否还需 Iris 等支持，不把下载称为已启用           |
| 整合包   | 在线列表、MRPACK/ZIP 识别、运行环境、体积/依赖预览                           | 默认新建实例                     | 在临时实例完成安装与校验后提交，不覆盖已有生存实例               |
| 数据包   | 搜索、游戏版本/包格式、安装影响说明                                          | 指定实例 + 指定世界的 datapacks/ | 游戏关闭时提交文件；启用与兼容性另行验证，安装不等于已在世界启用 |
| 资源包   | 搜索、游戏版本/包格式、分辨率/说明                                           | 实例 resourcepacks/              | 文件提交；后续安全调整 options.txt 后才可称“已启用”              |

下载内容详情提供返回结果、简介、支持版本、作者/来源、项目链接、安装目标、将添加/替换的文件清单。首期采用右侧内容内的详情页，不再在右侧额外切出第三个常驻栏。

流程：**搜索 → 查看详情 → 选择文件版本与安装目标 → 检查依赖/冲突并预览变更 → 安装 → 查看真实结果**。只查询失败就保留搜索条件和旧结果，标记旧结果时间；无兼容版本明确提示，不自动跨版本装入。说明只根据元数据兼容，不保证所有 Mod 组合可运行。

资源源先接入 Modrinth，原因是其官方搜索接口提供项目类型、版本等筛选，版本接口提供文件与依赖结构；实施时锁定适用 API 版本并按接口真实能力处理分类，避免硬编码站点展示推断。依据：[搜索](https://docs.modrinth.com/api/operations/searchprojects/)、[项目版本](https://docs.modrinth.com/api/operations/getprojectversions/)、[版本详情](https://docs.modrinth.com/api/operations/getversion/)。

CurseForge 放到单独增量：只有取得适用的 API 凭据、确认发行与文件下载条件后才启用；密钥不得写在前端或仓库。对于不能直接下载的文件显示原项目入口，不绕过平台限制。首期不为了来源切换创建通用插件市场或庞大资源提供者框架。

MRPACK 导入遵循[官方格式](https://support.modrinth.com/en/articles/8802351-modrinth-modpack-format-mrpack)：路径受限、文件哈希、客户端/服务端条件、依赖和 overrides 都必须处理。常见 ZIP 只在识别到支持的清单时进入安装；未知 ZIP 仅检查内容，不猜测为整合包。拖入文件始终先出现检测与变更预览，不直接安装或执行。

## 7. 账户、任务与交互约定

左下固定：皮肤头部头像、玩家名、账户类型、展开箭头。左键打开账户面板，选择正版/离线、用户名、皮肤；右键可提供当前账户管理菜单，不能用右键直接退出账户。现阶段账户存储是一个正版档案加离线身份，不应设计成已具备完整多账户保险库；多正版账户切换后续另做。

头像必须来自实际皮肤，失败时回退默认头像。不要用绿色圆点表达含糊的“在线”：账户类型不等于联网状态，也不等于令牌仍有效。正版认证失败给出重新登录路径，不自动切换离线。离线头像当前只用于启动器，面板保持说明。

| 操作                    | 结果                                                         |
| ----------------------- | ------------------------------------------------------------ |
| 单击主入口              | 切换左栏和右侧；不丢失其他入口的位置                         |
| 单击实例/分类           | 更新右侧内容；左栏保持位置                                   |
| 右键实例                | 该实例的操作菜单，不触发启动                                 |
| 双击实例                | 默认只选择；用户开启后才启动，运行中不重复启动               |
| 拖动分隔条 / 左右方向键 | 调整左右宽度并保存；键盘有明确焦点                           |
| 拖入 ZIP/MRPACK         | 原生受限读取 → 检测 → 预览 → 明确安装动作                    |
| 安装中切页              | 原生任务继续，底部任务摘要跟随全部页面                       |
| 游戏运行中打开存档      | 可以显示已有信息，但写入锁定；退出后重新读取                 |
| 关闭启动器且游戏在运行  | 明确提示当前会结束其游戏进程；先提供取消关闭，不静默结束世界 |

底部任务摘要显示当前真实阶段；点击展开任务抽屉，提供日志、取消、失败原因和重试。不能测量时显示“不确定进度”，不编造百分比。取消下载和结束游戏使用不同文案，运行中的游戏不能显示“下载已完成 100%”代替进程状态。

当前宿主只允许一个运行任务。首个 UI 版本如实保持该限制：待办安装只存在列表里，不启动并行工作。多下载队列与游戏并行需要后端调度和目标实例锁完成后再开放；游戏/认证/下载取消不能共享一个无目标的全局取消入口。

## 8. 视觉系统

| 项目     | 建议                                                                     |
| -------- | ------------------------------------------------------------------------ |
| 风格     | 聊天软件式稳定双栏、Minecraft 式适度方块纹理；清晰而不玩具化             |
| 亮色     | 背景 #F2F4F1，卡片 #FFFFFF，文字 #202B25，强调 #3D913D                   |
| 暗色     | 中性深板岩 #171D1B，卡片 #222B26，文字 #E7ECE7，强调 #8CCB80             |
| 色彩约束 | 绿色集中在选中、主按钮与状态；石色用于正文结构，不整屏染绿               |
| 形状     | 卡片 10–12px 圆角、输入框 6–8px、细边框；纹理低对比，不铺在文字下        |
| 字体     | Windows 系统中文字体，正文 13–14px，标题 20–24px；像素字仅可用于少量装饰 |
| 间距     | 8px 基础网格，卡片内 16–20px，分区 20–24px，列表行约 64–76px             |
| 图标     | 统一现有 Lucide；三个顶部入口同时有文字，不只靠图标记忆                  |
| 动态     | 120–180ms 轻过渡，遵守减少动态效果；不依赖真实亚克力模糊或高耗 GPU 特效  |

主题先保留现有深浅选择并继承老用户偏好；视觉预览以草白亮色演示。背景图可本地导入，提供遮罩保证可读；跨重启保存必须复制到受控素材目录，不持久化失效 blob URL。Minecraft 纹理、皮肤、截图区分各自来源，只使用用户提供、可授权或原创素材。

选中态同时用背景、细条和文字表现；文字/背景对比度目标至少 4.5:1，控件边界/焦点 3:1，不能只靠红绿区分状态。菜单支持键盘导航；对话框管理焦点，关闭后回到触发按钮。最小 32px 点击范围，重要按钮 36–40px。

## 9. 必须覆盖的页面状态

| 状态              | 呈现和恢复路径                                                  |
| ----------------- | --------------------------------------------------------------- |
| 无实例            | 游戏库安装/导入引导；不展示样例作为真实实例                     |
| 无账户            | 显示选择账户，启动按钮指向明确的账户操作                        |
| 无世界/Mod/截图   | 对应空态及下一步，无虚假数量                                    |

## 11. 内容安装的实现约束

新增资源安装复用现有下载校验和安全路径机制，但按来源显式增加受信域名，不能为第三方资源把原下载域名限制全部放开。来自 API 的路径、文件名、HTML/Markdown 说明和 ZIP 都按不可信输入处理；不渲染可执行脚本，不运行包内安装脚本。

安装步骤：解析目标和条件 → 生成文件变更计划 → 获取目标实例/世界锁 → 下载临时文件并校验 → 备份被替换文件 → 原子提交 → 写安装记录。失败/取消时清理未提交文件，提交过程中有日志可恢复；整合包先在新临时实例安装，成功后才加入清单。更新不能依赖一个“下载成功”通知就认定全部文件一致。

Mod 元数据读取区分 Fabric/Forge 等格式；第一期仅支持已验证的 Fabric 路径。普通启停仅对受控实例中已识别文件改名 .jar ↔ .jar.disabled，不删除，检查目标重名和占用。必需依赖有完整版本条件时才自动解析；缺少、冲突、环或条件不明确时阻止自动安装并解释，不盲目装最新版本。

备份恢复需要验证备份归属和目标修订，再展示将恢复内容；备份不是无限累积，保留策略后续独立设置。截图/目录打开命令只允许已注册实例受控目录，不能前端传一个任意路径交给 Shell。

## 13. 验收与回归

1. 三个图标位置和顺序固定；切设置时左侧不再显示实例列表，切下载时显示六类资源，回游戏库恢复原选择。
