# V0.3 第一阶段：账户、内存、Fabric 与整合包检查

验证日期：2026-10-23。

本轮按用户要求先完成账户与内存体验，再推进规格中 V0.3 的分步实现。没有把这一阶段描述为完整的 Mod/整合包生态。

## 已实现

- 左下角头像直接打开账户弹窗，可选择正版/离线登录，左栏展示真实身份。设备授权轮询由应用服务持有，关闭弹窗不中断。Client ID 一次配置后保存；本人 Microsoft 授权仍未验收。
- 实际 Windows 物理/可用内存检测、自动与手动分配、滑块/数值输入、系统余量提示，启动日志记录实际 `-Xmx` 上限。新配置默认自动；旧配置保留原手动上限。
- 可选内存整理默认关闭。手动“仅整理启动器”仅处理 Easy Craft 主进程自身；“系统内存整理”需二次确认，使用 Windows 工作集 API 尝试处理当前权限可访问进程，无权限进程跳过。勾选启动前整理后会在游戏启动前执行系统整理。不结束程序、不修改权限、不清空内核缓存，不承诺固定释放量；后续访问页面可能造成短暂卡顿。
- Fabric 稳定版本查询、独立实例安装、官方 Maven 依赖下载与 SHA-1 校验、内容哈希锁定配置、KnotClient 启动参数。实例只在安装成功后加入清单；不自动安装 Fabric API 或 Mod。
- ZIP/MRPACK 内容检查与依赖/文件清单预览，识别 CurseForge manifest。拒绝越界路径、符号链接、重复/大小写冲突文件名、过多条目和过大展开体积。MRPACK 检查游戏/加载器依赖、哈希字段格式、大小和官方 Modrinth CDN 下载来源。

## PCL2 源码核对

工作区两份源码中的 `Plain Craft Launcher 2/Pages/PageOther/PageOtherTest.xaml.vb` 第 12–16 行，`MemoryOptimize` / `MemoryOptimizeInternal` 均为“开源内容中不包含百宝箱功能”的占位实现。启动流程、设置开关和卡顿/权限提示保留。因此本项目参考使用方式，内存整理是独立实现，未复制或声称复用了缺失的核心算法，也不声称达到 PCL 所描述的固定比例效果。

Windows API 依据：[GlobalMemoryStatusEx](https://learn.microsoft.com/windows/win32/api/sysinfoapi/nf-sysinfoapi-globalmemorystatusex)、[EmptyWorkingSet](https://learn.microsoft.com/windows/win32/api/psapi/nf-psapi-emptyworkingset)。Fabric API 依据：[Fabric Meta](https://github.com/FabricMC/fabric-meta)。MRPACK 格式依据：[Modrinth 格式说明](https://support.modrinth.com/en/articles/8802351-modrinth-modpack-format-mrpack)。

## 复现

```powershell
npm run build
npm test
npm run test:e2e
npm run lint
npm run format:check
.\scripts\native.ps1 test
.\scripts\native.ps1 test -Integration fabric
.\scripts\native.ps1 clippy
.\scripts\native.ps1 fmt
.\scripts\native.ps1 build
node scripts/smoke-native.mjs debug --launch-offline --fabric
.\scripts\native.ps1 bundle
node scripts/smoke-native.mjs release --launch-offline --fabric
```

桌面检查使用 `.native/integration` 独立目录，临时保存并还原设置，不修改用户的 `data` 或其他启动器数据。系统整理开关会测试保存，但在启动游戏前关闭，不执行全局整理。
